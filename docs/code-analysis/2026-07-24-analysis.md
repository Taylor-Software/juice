## Headline

Health is high and **every HIGH finding from the 2026-07-04 report has been closed** —
per-keystroke sheet persistence (`DebouncedTextField`, adopted across 15 files), engine
purity (`lib/engine/` no longer imports `flutter/`), the 14× sheet-dispatch copy-paste
(`_premadeSheetView`), and both uncached search scans (250 ms debounces). Coverage rose to
85.5 %, no secrets, no dead files, no unused dependencies, disposal hygiene clean, no TODO
or FIXME anywhere in `lib/`. There are **no critical findings**.

What's left is structural, and it clusters in one place: **the 16-system character-sheet
layer**. Adding a system today means touching ~42 sites in `models.dart` plus four other
files, and each sheet view carries its own private copy of a stepper widget and its own
unseeded `Random()`. The top three priorities: (1) route sheet rolls through the `Dice`
seam so they're deterministic and testable, (2) delete the 11 duplicated `_stepper`
copies in favour of the shared `intStepper` that already exists, and (3) start splitting
the 5,663-line `models.dart`.

## Findings

### 🔴 Critical

- None found.

### 🟠 High

- **H1 — Sheet dice rolls bypass the `Dice` seam and are untestable.**
  `lib/features/argosa_sheet.dart:50`, `cairn_sheet.dart:53`, `knave_sheet.dart:49`,
  `ose_sheet.dart:49`, `embark_sheet.dart:53`, `kal_arath_sheet.dart:49-50`,
  `dcc_sheet.dart:88,251,253,301,342`, `draw_steel_sheet.dart:53`, `custom_sheet.dart:310`
  all call bare `Random()` in the UI layer. Every other roll in the app goes through
  `Dice(rng)` (`lib/engine/dice.dart:5`) or `oracleProvider`, which is what makes engine
  rolls seedable and unit-testable. These eleven don't, so no test can assert that an
  Argosa roll-under, a DCC save, or a Kal-Arath 2d6 actually classifies correctly — the
  *classification* logic lives inline in the widget too, which is the same mixed-concerns
  problem. Fix: read the injected `Dice` (or `oracleProvider.dice`) and lift the
  pass/fail banding into a pure helper per system.
  *Complexity: medium.*

- **H2 — `_stepper` is defined 11 times; `intStepper` already exists to hold it.**
  `argosa_sheet.dart:22`, `nimble_sheet.dart:20`, `dcc_sheet.dart:29`,
  `embark_sheet.dart:26`, `draw_steel_sheet.dart:26`, `knave_sheet.dart:22`,
  `cairn_sheet.dart:22`, `ose_sheet.dart:22`, `kal_arath_sheet.dart:22`,
  `funnel_sheet.dart:24`, `verdant_screen.dart:342` each carry a ~25-line private
  stepper — while `lib/features/sheet_widgets.dart:114` already exports `intStepper`
  for exactly this. The private copies are a strict superset (they add `label`, `min`,
  `max`); widening `intStepper` with those three optional params and deleting the copies
  removes **~250 LOC** and one whole class of drift.
  *Complexity: trivial. Highest LOC-per-effort item in this report.*

- **H3 — `Character` carries 16 nullable sheet fields; adding a system is shotgun surgery.**
  `lib/engine/models.dart:4431-4520`. Each new sheet system must be threaded through the
  constructor, a field, `Character.forSheet`, `copyWith` (plus a `clearX` flag),
  `withHpDelta`, `toJson`, `fromJson`, and `characterHpPool` — **42 enumeration sites in
  `models.dart` alone**, plus `tracker_screen.dart` (11), `encounter_screen.dart` (9),
  `quick_ref.dart` (7) and `funnel.dart` (6). The compiler cannot tell you when you miss
  one; a forgotten `toJson` branch silently drops a player's sheet on export.
  Fix: a `SheetKind`-keyed `Map<String, SheetData>` behind a small interface
  (`toJson` / `copyWith` / `hpPool`), so a new system registers once.
  *Complexity: invasive — worth planning, not worth doing casually.*

- **H4 — `lib/engine/models.dart` is 5,663 LOC across 60 top-level classes.**
  It holds the entire domain: 16 character sheets, the map/dungeon/settlement model,
  encounter state, decks, sessions, settings, and the world trackers. Splitting along
  seams that already exist (`models/sheets.dart`, `models/map.dart`, `models/session.dart`)
  is mechanical and would make H3 tractable.
  *Complexity: medium (mechanical, but touches ~90 import sites).*

### 🟡 Medium

- **M1** `lib/state/providers.dart:1971-2460` — ten near-identical one-key
  SharedPreferences notifiers (`AiEnabled`, `AiNudgeSeen`, `Welcome`, `AiOfferSeen`,
  `TrackHelpSeen`, `ChipHelpSeen`, `RecapSuppressed`, `PlayPanelExpanded`,
  `CloudInterpretEnabled`, `SplitView`) plus `LastExport` (`int?`) and `TextScale`
  (`double`). Each is ~15 lines of the same build-read / write-and-set-state shape.
  A `_PersistedFlag(key, default)` base — the sibling of the `_PersistedList` that
  already deduplicates the nine list notifiers — removes **~150 LOC**. *Trivial.*

- **M2** `lib/features/fate_screen.dart:118` — a **481-line** `build()`. Distinct sections
  (oracle, moves, cards, spreads, My Oracles) are already visually delimited; extracting
  each to a `Widget _xSection()` mirrors what the file does at `:622` and `:659`.
  Same shape at `journal_screen.dart:796` (304 lines) and `loop_bar.dart:70` (287).
  73 methods in `lib/` exceed 80 lines. *Trivial each, medium in aggregate.*

- **M3** `lib/shared/home_shell.dart:382, 422, 491, 571` — the FilePicker preamble
  (pick → `PlatformException` catch → snackbar → pop → extract `files.first.bytes` →
  bail on null) is copy-pasted **4×** across campaign import, table-pack import, and
  oracle-pack import. A `Future<Uint8List?> _pickBytes({title, extensions})` helper
  collapses ~60 LOC and guarantees the four paths handle a denied file permission
  identically. *Trivial.*

- **M4** `lib/features/journal_screen.dart:2827`, `tracker_screen.dart:2017`,
  `encounter_screen.dart:548` — the tag-editor dialog (controller, autofocus field,
  Cancel/Add actions, post-frame dispose, trim-and-dedupe) is duplicated three times
  with only the target collection differing. *Trivial.*

- **M5** `lib/state/auto_backup.dart:64` — the rolling auto-backup swallows **all**
  exceptions with an empty catch. The comment justifies it for web/test platforms, but
  it equally hides a full disk or a revoked directory permission: backups then fail
  forever, silently, on a feature whose entire purpose is data safety. The 7-day export
  nudge is a weak backstop (`stamp()` is inside the same `try`, so it correctly won't
  fire — but the user is told "back up soon", not "backups are failing"). Fix: retain
  the last error and surface it in the existing Settings/export UI. *Trivial.*

- **M6** `lib/features/settings_sheet.dart` — **46.9 % covered, 112 uncovered lines**,
  the largest real coverage gap. This file owns the AI enable gate, the model download
  consent flow, and the cloud API-key entry — the three places where a regression is
  both most likely (async, platform-dependent) and most costly (a billable key). *Medium.*

- **M7** `lib/features/battle_pane.dart` (1.3 %, 78 uncovered) and
  `lib/features/resources_pane.dart` (1.6 %, 62 uncovered) — effectively untested, and
  neither is imported by any test. Unlike the platform seams below, these are ordinary
  widget code that a widget test could cover. *Trivial.*

- **M8** `lib/state/providers.dart` — 71 direct `SharedPreferences.getInstance()` calls
  (77 in `lib/` total). Every one is an await on a platform channel with no seam, so
  storage behaviour can only be tested via `setMockInitialValues`. Given `_PersistedList`
  and the M1 base class both funnel through it, one injected `Future<SharedPreferences>`
  provider would centralise it. *Medium.*

- **L4** `.metadata`, `macos/Flutter/GeneratedPluginRegistrant.swift`, and `pubspec.lock`

### 💡 Ideas

- **I1** The `colorScheme.` migration ratchet sits at **131** (`test/design_system_test.dart:148`)
  against 37 `context.juice` uses. The ratchet works — it only goes down — but it has no
  schedule. Consider tying a small decrement (say −10) to each UI-touching PR so the debt
  actually retires rather than merely not growing.
- **I2** The lint bar could rise. `flutter_lints` + 7 rules + strict-casts/raw-types is
  already above average, but `very_good_analysis` (or just adding
  `always_declare_return_types`, `prefer_const_constructors_in_immutables`,
  `avoid_positional_boolean_parameters`) would catch the H2/M1 duplication class earlier.
  Do this **after** H2/M1, not before — otherwise it lands as a large mechanical diff.
- **I3** H1 + H3 together suggest a `SheetSystem` registry: one object per system holding
  its stat keys, its roll resolver (pure, `Dice`-injected), its `FunnelProfile`, its
  QuickRef card, and its JSON codec. That is the shape the codebase keeps re-deriving
  in five separate lookup tables.
